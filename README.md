# eLine — электронная запись студентов

Веб-сервис электронной записи студентов на услуги университета.

**Рабочая версия:** [university.megafonhome.ru](https://university.megafonhome.ru/)
Система предназначена для подачи, обработки и контроля заявок студентов, а также для управления расписанием и доступными временными интервалами.
---

## Назначение

В системе предусмотрены три роли пользователей:

* **Студент** — работа с услугами, расписанием и собственными заявками.
* **Сотрудник** — обработка заявок студентов и расширенная работа с расписанием.
* **Администратор** — все возможности сотрудника и дополнительные административные функции.

Модель доступа построена по принципу расширения возможностей:

$$\text{Студент} \longrightarrow \text{Сотрудник} \longrightarrow \text{Администратор}$$

> **Обратите внимание:** Это логическая модель возможностей, а не наследование классов или ролей в PHP. Фактический доступ к каждой операции определяется серверной проверкой разрешённых ролей.

---

## Основные возможности

### Студент
* просмотр доступных услуг;
* просмотр расписания;
* выбор даты и времени;
* создание заявки;
* просмотр собственных заявок и их статусов;
* просмотр информации о записи;
* удаление заявки в разрешённых состояниях.

### Сотрудник
Имеет базовые возможности студента, а также:
* просмотр, поиск, фильтрация (по статусу) и сортировка заявок студентов;
* просмотр подробной информации по заявке;
* подтверждение и отклонение заявок;
* изменение статуса заявки и принятие её в работу;
* назначение ответственного сотрудника;
* перенос записи;
* добавление административных комментариев;
* просмотр истории изменений;
* управление доступностью временных интервалов.

### Администратор
Имеет возможности сотрудника, а также:
* управление расписанием;
* автоматическая генерация расписания;
* выполнение административных операций.

В дальнейшем предусмотрено расширение административной части для:
* создания и редактирования услуг;
* управления сотрудниками и изменения ролей пользователей;
* дополнительных системных настроек.

## Архитектура

Проект построен по клиент-серверной архитектуре:

$$\text{React (Frontend)} \longrightarrow \text{PHP API (Backend)} \longrightarrow \text{MySQL (Database)}$$

* **Frontend** отвечает за пользовательский интерфейс и взаимодействие с пользователем.
* **PHP API** отвечает за серверную логику, авторизацию, управление сессиями, проверку ролей, обработку запросов и взаимодействие с базой данных.
* **MySQL** используется для постоянного хранения данных.

> React не подключается напрямую к MySQL.

### Frontend
Клиентская часть реализована с использованием **React**, **JavaScript**, **Vite**, **HTML** и **CSS**.

Frontend отвечает за:
* пользовательский интерфейс и навигацию;
* состояние приложения и отображение данных;
* отправку запросов к API;
* отображение функций в соответствии с ролью пользователя.

Production-сборка создаётся с помощью Vite.

### Backend
Серверная часть реализована на **PHP**.

Backend отвечает за:
* авторизацию и управление пользовательскими сессиями;
* проверку ролей и бизнес-логику;
* обработку API-запросов;
* взаимодействие с MySQL (используется **PDO**);
* формирование ответов для frontend.

### База данных
Для хранения данных используется **MySQL**. В базе хранятся:
* пользователи;
* услуги;
* расписание и временные интервалы;
* заявки и статусы заявок;
* история изменений;
* административные комментарии;
* ответственные сотрудники.

> React не содержит параметров подключения к MySQL. Подключение к базе данных выполняется только серверной частью PHP.

## API

API является промежуточным серверным слоем между React-приложением и MySQL. Браузер не имеет прямого доступа к базе данных.

### Основные API-методы

| API-метод | Назначение |
| :--- | :--- |
| `getCurrentUser.php` | Получение текущего пользователя |
| `getServices.php` | Получение списка услуг |
| `getSchedule.php` | Получение доступного расписания |
| `addRequest.php` | Создание заявки |
| `getRequests.php` | Получение заявок с учётом роли |
| `updateRequest.php` | Изменение заявки |
| `deleteRequest.php` | Удаление заявки |
| `moveRequest.php` | Перенос записи |
| `getRequestHistoryByID.php` | Получение истории заявки |
| `getScheduleAdmin.php` | Получение расписания в расширенном режиме |
| `updateScheduleFieldisActive.php` | Включение или отключение временного интервала |
| `addScheduleGenerator.php` | Автоматическая генерация расписания |

## Безопасность и разграничение доступа

### Авторизация и сессии
Для авторизации используются серверные PHP-сессии. После авторизации сервер создаёт пользовательскую сессию, а браузер сохраняет её идентификатор в cookie.

Для запросов, использующих серверную сессию, React передаёт:
```javascript
credentials: "include"

```

При запуске приложения React получает информацию о текущем пользователе через API и определяет состояние авторизации и роль. Если пользователь не авторизован, защищённые разделы приложения ему недоступны.

Каждый защищённый API endpoint самостоятельно проверяет наличие действующей сессии и права пользователя. HTTP-запрос к защищённому API без действующей сессии отклоняется серверной частью.

### Модель разграничения доступа (RBAC)

В проекте используется модель **RBAC (Role-Based Access Control)**.

Проверка прав выполняется непосредственно на backend с помощью функции `requireRole(...)`:

* **Операция доступна всем трём ролям:**
```php
requireRole(["student", "employee", "admin"]);

```


* **Операции сотрудника и администратора:**
```php
requireRole(["employee", "admin"]);

```


* **Административные операции:**
```php
requireRole(["admin"]);

```



### Защита данных

* Production-версия системы работает через **HTTPS**.
* Защищённые API-методы проверяют сессию, текущего пользователя, его роль и разрешённость операции.
* Параметры подключения к MySQL и другие серверные настройки хранятся исключительно на сервере.
* Работа с MySQL выполняется через **PDO** с использованием подготовленных выражений (prepared statements) для защиты от SQL-инъекций.

## Управление заявками

Заявка является основной сущностью системы.

### Жизненный цикл заявки

```text
Ожидает подтверждения ──► Подтверждено ──► В обработке ──► Готово к выдаче ──► Завершено
         │                                       │
         └───────────────────► Отклонено ◄───────┘

```

Доступные действия зависят от текущего состояния заявки и роли пользователя. При изменении состояния сохраняется время изменения. Для заявки в обработке может быть назначен ответственный сотрудник.

### История заявок

Для заявок предусмотрено хранение истории значимых изменений (изменения статуса, комментарии, перенос времени записи). Доступ к истории предоставляется сотрудникам и администраторам через метод `getRequestHistoryByID.php`.

## Расписание и услуги

### Расписание

Расписание состоит из отдельных временных интервалов:

* **Студент:** просмотр доступного расписания (`getSchedule.php`).
* **Сотрудник / Администратор:** расширенный доступ и управление доступностью интервалов (`getScheduleAdmin.php`, `updateScheduleFieldisActive.php`).
* **Администратор:** автоматическая генерация расписания (`addScheduleGenerator.php`).

При создании заявки выбранный временной интервал связывается с заявкой в базе данных и становится недоступным для повторного выбора.

### Услуги

В системе предусмотрен каталог услуг университета, используемый студентами при создании заявок. В дальнейшем планируется расширение интерфейса для административного управления услугами (создание, редактирование, изменение категорий и параметров).

## Развёртывание и запуск

### Серверное окружение

Production-версия проекта развёрнута на VPS:

* **OS:** Ubuntu 24.04
* **Web Server:** Nginx
* **Backend:** PHP
* **Database:** MySQL
* **SSL:** Let’s Encrypt (Certbot)

**Рабочая версия:** [https://university.megafonhome.ru/](https://university.megafonhome.ru/)

### Запуск Frontend для разработки

1. **Установка зависимостей:**
```bash
npm install

```


2. **Запуск development-сервера:**
```bash
npm run dev

```


3. **Создание production-сборки:**
```bash
npm run build

```


Скомпилированные файлы приложения будут размещены в каталоге `dist/`.
